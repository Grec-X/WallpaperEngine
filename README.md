手机壁纸引擎
这是一个 Vibe Coding 项目——从第一行代码到发布，全程由人机对话完成，没有人手写代码。

人负责提需求、拍技术方案、真机验收和产品判断；AI（ZCode + GLM）负责方案撰写、写代码、 搭构建链，以及通过 adb 远程调试和日志取证。开发过程按阶段记在 docs/日志/ 里，包括 走过的弯路和放弃的方案。

功能上，它把手机里的视频设成 Android 动态壁纸，循环播放，桌面和锁屏可以分开设置。

实现了什么
桌面和锁屏分开设置
系统自带的壁纸设置只能放静态图，视频播一次就停。这个应用是一个完整的动态壁纸服务， 设好之后视频一直循环。

两个位置独立：桌面可以放一个视频，锁屏放另一个；也可以一边视频一边静态图。 两边的默认壁纸、音量、画面比例、循环区间都分开保存。

视频和图片
视频：循环播放，硬件解码，保持比例裁剪铺满
图片：作为静态壁纸提交给系统
播放设置
音量、填充模式（裁剪 / 拉伸）、循环区间。桌面和锁屏各存一份，改哪边就在顶部切到哪边。

壁纸库
右上角 ☰ 打开。历史和收藏各放 25 个，标题上实时显示数量。

自动记录用过的壁纸，同一个视频选两次不会重复占位置
超过 25 个时淘汰最旧的，连带清理视频文件和缩略图
收藏的条目不会被自动清理
桌面默认、锁屏默认分开设置，恢复时各回各的
省电
熄屏、锁屏、被其他应用完全盖住时自动暂停，回到桌面接着放。手机重启后壁纸自动恢复。

视频文件出问题时会回退到内置素材，主界面状态条标红提示「播放异常」，不会卡在某一帧。

怎么操作
第一次使用
打开应用，首次启动会请求「照片和视频」权限。这个权限用来读取系统当前的壁纸， 主界面卡片的缩略图显示的就是系统里真实的画面。拒绝也能用，只是卡片不显示缩略图。
点上方橙色的状态条，进入系统壁纸确认页，点确认完成绑定。确认页里可以选只设桌面、 只设锁屏，或者两者都设。
回到应用。
换壁纸
选新壁纸：点「选择桌面壁纸」或「选择锁屏壁纸」，从手机里挑视频或图片。 选完直接生效，不用再进系统页面。
用壁纸库里的：点 ☰，点任意缩略图，弹出「设置为」三个选项——桌面壁纸、锁屏壁纸、 桌面和锁屏壁纸。选哪个只影响哪个位置。
设默认壁纸
长按缩略图，选「设为桌面默认」或「设为锁屏默认」。设好之后缩略图右下角会标「桌面默认」 或「锁屏默认」。

之后点「恢复桌面默认」或「恢复锁屏默认」，一键回到对应的默认壁纸。

收藏和删除
长按缩略图：

「收藏」——缩略图左上角出现 ★，不会被自动清理
「从历史中删除」——连同视频文件和缩略图一起清掉
正在使用的壁纸和默认壁纸不能删，会提示先换掉。

调播放设置
主界面「播放设置」卡片顶部有个「编辑对象」开关，切到桌面或锁屏，下面的音量、 画面比例、循环区间就会载入对应位置的设置，改完自动保存。

循环区间可以裁掉片头片尾，只循环中间一段。

退回系统壁纸
「恢复桌面默认」/「恢复锁屏默认」——如果你没给那个位置设过默认壁纸，这两个按钮会把 该位置还原成系统原生壁纸，视频壁纸引擎随之退出。

注意事项
Debug 版不能直接安装

Debug 构建用 FastDev 增量部署，程序集不在 APK 里。卸载重装、系统里「清除数据」之后 应用会启动崩溃。开发时请用 deploy.cmd 重新部署，日常使用请装 Release 版（自包含）。

锁屏单独播视频有系统限制

需要 Android 14 以上的框架支持，并且厂商开放了这个能力。iQOO Neo 9（OriginOS 6） 实测可用；Android 13 及更早的系统上，锁屏会跟随桌面，应用会提示。

系统确认页只在需要建立绑定时出现

已经绑定好之后换壁纸是即时生效的，不会再弹系统页面。只有这两种情况会弹： 桌面或锁屏当时是静态画面（需要重新绑定动态壁纸），或者壁纸还没激活过。

确认页里如果改选了别的范围，配置和实际绑定可能暂时对不上。重新按正确的目标设置一次 就恢复。

设为静态壁纸会退出视频模式

桌面设成图片后，动态壁纸引擎就退出了，状态条会显示静态壁纸。想回视频就重新设置一次。

静态画面时播放设置不可用

某个位置正在显示静态图时，切到那个位置，音量和循环区间会变灰——静态图没有这些概念。

仓库里没有素材和工具链

内置素材（Assets/default.mp4）和开发工具链（约 3GB）没有入库。克隆后放一个 MP4 进去 再构建；不放也能跑，首次启动没有默认壁纸，自己选一个就行。

遇到过的坑
写在这里，省得别人再踩。

WallpaperService.Engine 在 Release 下编译不过

Engine 是 Java 内部类，.NET Android 的 ACW 生成器在 Release 模式下会把它的子类生成成 顶层 Java 类，javac 报「需要包含封闭实体」。Debug 模式不生成这些桥接代码，所以没事。

项目用构建后处理解决：fix-acw.ps1 在 _GenerateJavaStubs 之后改写生成产物，变成合法的 内部类形式。细节见 docs/日志/阶段04 补记 5。

中文路径导致 aapt2 打包失败

项目路径含中文时 aapt2 找不到 android.jar。现在建了 ASCII 目录联接 G:\WE， 构建脚本固定走这个路径。

ColorOS 的 WallpaperInfo 返回 null

标准 API WallpaperManager.WallpaperInfo 在 ColorOS 13.1 上永远返回 null，哪怕壁纸确实 是动态壁纸。判断壁纸是否激活只能看自己的引擎实例是否存活。

厂商确认页不返回结果

系统确认页没有结果回调，也没有范围查询接口。所以不能靠「确认后读回系统状态」来决定 壁纸该放到桌面还是锁屏——读到的只可能是上一次的状态。壁纸库里的三选菜单才是可靠方式。
