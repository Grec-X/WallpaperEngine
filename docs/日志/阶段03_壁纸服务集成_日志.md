**与方案 7 节的差异**：原定独立的 `WallpaperEngine.Service` 项目并入 App——壁纸服务必须与宿主 APK 同包注册，独立类库无部署意义；Core/Player 分库保持（阶段四 MAUI 管理应用直接引用）。PoC 工程归档于 `poc/` 不再演进。

### 2. 壁纸服务实现（方案 4.1 生命周期矩阵的正式落地）

- `[Service]` 声明：显式 Name（`com.wallpaperengine.app.VideoWallpaperService`，跨版本稳定）、`BIND_WALLPAPER` 权限、`Exported=true`、`IntentFilter(ServiceInterface)`、`MetaData(ServiceMetaData → @xml/video_wallpaper)`（thumbnail/description 资源）。
- `VideoEngine : WallpaperService.Engine`：
  - OnCreate → 读配置；OnSurfaceCreated → 装载视频+SetSurface+Prepare；OnVisibilityChanged → 可见播放/不可见暂停；OnSurfaceDestroyed → 暂停+解除 Surface（硬性约束）；OnDestroy → 释放内核；
  - 静态 `ActiveEngine` + `NotifyConfigChanged()`：管理界面换视频后热重载（无需重设壁纸）。
- 管理页（阶段三极简版）：状态显示（含"是否已激活"检测）、`ACTION_CHANGE_LIVE_WALLPAPER` 一键设壁纸（带 `ACTION_LIVE_WALLPAPER_CHOOSER` 兜底）、SAF 选视频 → 复制私有目录 `videos/`（自动清理旧文件）→ 更新配置 → 热重载。
- **默认素材内置**：`素材\灰原哀.mp4` 打包为 `Assets/default.mp4`（ASCII 名规避资产名编码问题），首次启动释放到私有目录并生成默认配置——装 APK 即有默认壁纸，不再依赖 adb push。
- 完整应用图标（播放三角+循环弧线 adaptive icon，修复了模板图标引用缺失问题）。

### 3. 构建链适配（两个新坑与解法）

| 问题 | 解法 |
|---|---|
| 类库项目也要求 AndroidSdkDirectory | 新增根目录 `Directory.Build.props` 统一注入（对所有子工程生效） |
| aapt2 打包 Assets 时对中文项目路径直接报错（APT2000 error，比阶段二的 warning 更严重） | 新建项目根 ASCII 联接 `G:\WE`，build.cmd/deploy.cmd 固化走联接路径构建；实际文件仍在项目目录，联接仅为别名 |

### 4. 绑定 API 新坑记录（给阶段四）

- `WallpaperService.ServiceInterface/ServiceMetaData` 在 using Android.App 时会被 `Context.WallpaperService` 属性名遮蔽 → 必须全限定 `Android.Service.Wallpaper.WallpaperService.*`。
- `WallpaperService.Engine` 绑定构造为 `Engine(WallpaperService __self)`（非无参）。
- Engine 回调参数是 `ISurfaceHolder`（I 前缀）。

## 补记 2：重启自恢复验证 + 启动延迟现象（2026-10-24 晚）

**验证结果**：✅ 通过。手机重启后 `mWallpaperComponent` 仍指向本服务，壁纸自动恢复（用户确认桌面最终回到灰原哀），进程自动运行（无需打开 App）。

**用户观察的现象**：重启后壁纸并非立即加载，先显示系统默认壁纸，"过一小段时间"才切换为视频壁纸。

**原因分解**（定性，下次冷启动时用 logcat 时间戳量化）：
1. **系统设计如此**：Android 开机先用静态 ImageWallpaper 顶上保证桌面可用，SystemUI 异步绑定 WallpaperService——所有动态壁纸（含系统自带）都有此过渡，非本项目缺陷；
2. **服务进程冷启动**：动态壁纸服务绑定后进程才启动。我们的 .NET 服务多一层 Mono 运行时初始化，**Debug 版（解释执行）尤其慢**；Release/AOT 后将显著改善；
3. **首帧渲染链**：ExoPlayer 创建 → 文件读取 → 硬解初始化 → 首帧上屏，约数百毫秒量级。

**优化路径**：阶段四 Release/AOT 构建后重新测量；若仍不满意，可研究 Engine OnCreate 提前预热（意义有限，瓶颈在系统绑定时机）。**结论：暂不处理，属系统级正常行为。**

## 补记 3：用户实测反馈驱动的三轮修复（2026-10-24 深夜）

用户实测陆续暴露 4 个问题，全部修复并复验通过：

### 修复 1：热重载缺 Prepare（换视频画面不更新）
- 现象：选新视频回桌面，壁纸不变。
- 根因：`ReloadFromConfig` 装载新源后未调用 `Prepare()`，ExoPlayer 停在 IDLE；且对同一组件重复"设为动态壁纸"系统不重建引擎，无法自愈。
- 修复：统一 **EnsurePlayback 机制**（装载→Prepare→就绪自动播），并挂到 `OnVisibilityChanged(true)` 自愈。

### 修复 2：视频比例变形（用户观察：为适配屏幕被缩放）
- 根因：ExoPlayer 默认 `VideoScalingMode.ScaleToFit` 是**拉伸填满**（不保宽高比）。
- 修复：接口新增 `SetScaleMode(bool cover)`，默认 **Cover**（`ScaleToFitWithCropping` 保持比例裁剪铺满）；Engine 按 `config.FillMode` 应用。Fit 模式（留黑边）需渲染中间层，记 V2。
- 绑定 API：`IExoPlayer.VideoScalingMode` 属性（int），常量用 `Android.Media.VideoScalingMode` 枚举。

### 修复 3：连续换视频后壁纸卡死（架构级三缺陷）
- 现象取证（run-as 读设备配置+目录）：配置指向的文件被后续导入清理删除 → 引擎内存配置过期 → `Source error 2005` 后卡死。
- 三个缺陷与修复：
  1. **回桌面自愈不重读配置**（只比对内存副本）→ `OnVisibilityChanged(true)` 现在**强制重读配置文件**；
  2. **文件失效无回退** → `ResolveVideoPath`：配置文件不存在时回退 default.mp4（缺失自动从 Assets 重新释放）；
  3. **源错误后卡死** → ErrorOccurred 重置装载记录、1 秒后重试一次（`_errorRetried` 防死循环）。
- App 侧：导入清理改保守策略（保留最近 2 份 wallpaper_*.mp4 + 默认素材，不删引擎可能正在播的文件）。

### 修复 4（伴随发现）：ColorOS 对强停壁纸服务的回退策略
- `am force-stop` 杀掉壁纸服务后，ColorOS **不重绑**第三方壁纸，直接回退系统自带动态壁纸（WavesLight）。
- 影响：开发调试时不可依赖 force-stop 刷新壁纸服务；需重新走"设为动态壁纸"。
- 用户视角：引擎未激活时"换视频/恢复默认"静默无效（配置已更新，但无引擎消费）→ **阶段四 UX 待办：醒目的激活状态提示**。
