## 1. 项目概述

### 1.1 目标
做一个 Android 视频动态壁纸引擎：用户从管理界面选择本地视频，设置为系统壁纸后，壁纸常驻循环播放，体验接近主流商业视频壁纸 App（流畅、无缝、省电）。

### 1.2 非目标（明确不做）
- iOS / 鸿蒙版本（iOS 系统不开放第三方视频壁纸 API，鸿蒙技术栈与 C# 不兼容，均无落地路径）。
- 在线视频流、壁纸商店、社区功能（未来可扩展，V1 不做）。
- 特效粒子渲染、多图层合成（Unity 类引擎的强项，本项目聚焦视频壁纸）。

### 1.3 关键体验指标（验收时以此为准）
- 循环播放无可感知卡顿/黑屏闪烁（接缝 ≤ 1 帧的过渡可接受，理想为完全无缝）。
- 壁纸运行时内存占用 < 100 MB，不触发系统后台查杀。
- 灭屏 / 锁屏 / 其他应用全屏 / 省电模式下自动暂停，恢复条件消失后自动续播。
- 滑动桌面、切换页面时渲染不掉帧（以真机实测为准）。

## 2. 关键决策记录

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 平台仅 Android | Android 原生支持动态壁纸（WallpaperService 机制）；iOS/鸿蒙无 C# 落地路径 |
| D2 | 技术栈：.NET MAUI + Android 平台层 C# | 管理界面用 MAUI 快速开发；性能关键路径全部下沉到平台层，直接调用系统 API |
| D3 | 播放内核：Media3 ExoPlayer（NuGet 绑定包），PoC 阶段可用系统 MediaPlayer 验证链路 | ExoPlayer 支持无缝循环（REPEAT_MODE_ONE）、格式兼容性好、自带 MediaCodec 硬解调度 |
| D4 | 循环策略：V1 用播放器原生循环；V2 增加 FFmpeg 交叉淡化预处理作为"完美循环"增强 | 先跑通链路，无缝循环的品质化增强放在后续阶段 |
| D5 | V1 范围 = 最小可用版 | 本地视频 → 设为壁纸 → 循环播放 + 基础省电暂停，先验证可行性 |
| D6 | 性能原则 | 解码渲染走硬件直通（MediaCodec → Surface），C# 只做编排控制，不参与像素处理，性能与原生应用等价 |

## 3. 系统架构

### 3.1 分层结构

```
┌───────────────────────────────────────────────┐
│  管理应用（MAUI）                              │
│  视频选择 / 预览播放 / 设为壁纸 / 设置          │
├───────────────────────────────────────────────┤
│  核心逻辑层（C# 类库，无 UI 依赖）              │
│  壁纸元数据管理 / 配置读写 / 缩略图缓存          │
├───────────────────────────────────────────────┤
│  播放内核抽象层（IVideoLoopPlayer 接口）         │
│  ┌─────────────────┐  ┌────────────────────┐  │
│  │ ExoPlayer 实现   │  │ MediaPlayer 实现    │  │
│  │ (正式方案)       │  │ (PoC 备选)          │  │
│  └─────────────────┘  └────────────────────┘  │
├───────────────────────────────────────────────┤
│  壁纸服务层（Android 平台层 C#）                │
│  VideoWallpaperService : WallpaperService     │
│  Engine 生命周期 / Surface 管理 / 暂停策略      │
├───────────────────────────────────────────────┤
│  Android 系统：MediaCodec 硬解 → Surface 合成   │
└───────────────────────────────────────────────┘
```

### 3.2 组件职责

**壁纸服务层**（最关键的一层）
- 继承 Android 的 `WallpaperService`，在清单文件中注册为动态壁纸，带 `android:settingsActivity` 指向管理页。
- `Engine` 是系统与播放内核之间的桥：系统在壁纸可见/不可见、Surface 创建/销毁时回调 Engine，Engine 据此启动/暂停/释放播放器。
- 持有播放内核实例，把 Surface 交给它渲染。

**播放内核抽象层**
- 定义统一接口（Prepare / Play / Pause / Release / SetSurface / SetVolume / SetLoopMode / OnLoopCompleted 等），上层不感知具体播放器。
- 两个实现：ExoPlayer（正式）、MediaPlayer（PoC 阶段快速验证）。
- 这一层隔离了未来更换内核（如 FFmpeg 自渲染）的成本。

**核心逻辑层**
- 壁纸元数据（当前壁纸路径、裁剪点、音量、亮度、填充模式等）的读写，JSON 持久化在应用私有目录。
- 视频导入：从系统选择器取得视频后复制/记录到应用私有目录，生成缩略图与时长、分辨率信息。

**管理应用**
- MAUI Shell 应用，V1 页面流：首页（当前壁纸预览 + "选择视频" + "设为壁纸"）→ 系统壁纸确认页。

### 3.3 配置数据模型（V1 字段表）

| 字段 | 类型 | 说明 |
|---|---|---|
| videoPath | string | 视频文件路径（应用私有目录内） |
| originalName | string | 原始文件名（展示用） |
| durationMs | long | 视频时长（毫秒） |
| width / height | int | 视频分辨率 |
| volume | float 0~1 | 静音为 0（壁纸默认静音） |
| fillMode | enum | Cover（裁剪铺满，默认）/ Fit（留边适应） |
| brightness | float 0.2~1 | 画面压暗系数（省电+夜间不刺眼） |
| createdAt | datetime | 设置时间 |

## 4. 关键技术设计

### 4.1 壁纸服务生命周期（难点一）

系统对 Engine 的回调序列决定播放器动作，必须严格对齐，否则黑屏或泄漏：

| 系统事件 | Engine 动作 |
|---|---|
| onCreate(SurfaceHolder) | 初始化播放内核（不立即播放） |
| onSurfaceCreated | SetSurface → Prepare → Play |
| onSurfaceChanged(w,h) | 通知内核更新渲染目标尺寸 |
| onVisibilityChanged(false) | Pause（保留实例，记录播放进度） |
| onVisibilityChanged(true) | Play（从暂停处续播） |
| onSurfaceDestroyed | Pause + 释放 Surface 引用（必须在返回前完成，否则系统报错） |
| onDestroy | Release 播放内核，释放全部资源 |

特别注意：`onSurfaceDestroyed` 要求在方法返回前完成 Surface 的释放操作，这是与普通 Activity 视频播放最大的差异点，PoC 阶段要重点验证。

### 4.2 无缝循环策略（难点二，本项目的核心价值）

| 策略 | 无缝程度 | 实现成本 | 采用阶段 |
|---|---|---|---|
| ExoPlayer REPEAT_MODE_ONE | 大多数视频无缝，个别编码（如尾部 B 帧、音轨对齐问题）首尾有 1~2 帧跳变 | 低（一行配置） | **V1** |
| FFmpeg 预处理交叉淡化 | 完全无缝（首尾 N 秒交叉淡化烘焙进新视频） | 中（导入耗时几秒，需处理进度反馈） | V2 增强 |
| 往复播放（正放+倒放） | 完全无缝 | 中高（需自管解码缓冲） | V2 可选 |

V1 验收时如真机接缝明显，则提前把"交叉淡化"拉入 V1 收尾，作为风险预案。

### 4.3 功耗与暂停策略矩阵

| 触发条件 | 检测方式 | 动作 |
|---|---|---|
| 灭屏 | 系统广播 ACTION_SCREEN_OFF | 暂停 |
| 锁屏显示 | Engine 可见性回调 | 暂停 |
| 其他应用全屏遮挡 | Engine 可见性回调 | 暂停 |
| 省电模式 | 系统电源管理查询 | 暂停（可设置里关闭此行为） |
| 电量低于 15% | 电池状态广播 | 暂停（V2） |
| 恢复条件 | 对应事件反向触发 | 从断点续播 |

帧率策略：iQOO Neo 9 为 144Hz 屏，壁纸不追求满帧。V1 跟随视频原生帧率渲染；V2 增加帧率上限设置（30/60fps）用于省电。

### 4.4 性能设计

- 解码：ExoPlayer 底层 MediaCodec 硬解，视频帧直接渲染到 Surface，不经过 C# 内存，无逐帧托管开销。天玑 9200+ 对 4K H.264/H.265 均有硬件解码支持。
- 编排层（C#）：只在生命周期事件和循环事件时被调用（每循环一次），运行时开销可忽略。
- 内存预算：播放器实例 + 解码缓冲约 50~80 MB，符合 < 100 MB 目标；壁纸进程不加载 MAUI UI（服务与 App 同进程但延迟初始化，或评估独立进程，PoC 后定）。
- 禁止事项：不用 TextureView 做壁纸渲染（额外一次 GPU 合成、功耗更高），直接用 Engine 的 SurfaceHolder Surface。

### 4.5 权限与存储

- 视频导入：V1 采用系统文档选择器（SAF，`ACTION_OPEN_DOCUMENT`）——免存储权限、全 Android 版本可用、不依赖 Google 服务。注意：Android 13+ 的系统 Photo Picker 在国产 ROM 上不可用（无 GMS），且备用测试机 Reno6 Pro 为 Android 11 基线，此路完全不通，SAF 是唯一稳妥方案。
- `READ_MEDIA_VIDEO`（Android 13+）仅在后续版本需要浏览整个媒体库时引入，V1 不需要。
- minSdk = 26（Android 8.0），targetSdk = 34：向下覆盖备用测试机及市面绝大多数在役设备。
- 视频文件：导入后复制到应用私有目录（`Files` 目录），避免源文件被移动/删除导致壁纸失效。
- 清单声明：动态壁纸 service 声明 + `android.permission.BIND_WALLPAPER` 权限约束。

## 5. 阶段规划（四阶段）

### 阶段一：方案设计与技术调研 ✅（本阶段）
产出：本文档 + 阶段日志。无代码。

### 阶段二：核心播放 PoC（下一阶段）
- 目标：用一个单页 Android 测试工程（非完整 App）验证三件事：① C# 能否正确继承并驱动 ExoPlayer（NuGet 绑定可用性）；② 全屏 Surface 上循环播放的接缝表现（真机）；③ Engine 生命周期对齐逻辑能否跑通。
- 步骤：搭工程 → MediaPlayer 5 分钟链路验证 → 切 ExoPlayer 绑定 → 真机接缝评估 → 出 PoC 结论写入日志。
- 验收标准：iQOO Neo 9 真机上，一个测试视频全屏循环播放 30 分钟，无崩溃、无明显接缝、内存 < 100 MB。

### 阶段三：壁纸服务集成
- 目标：VideoWallpaperService 落地，测试工程能以"动态壁纸"身份出现在系统壁纸选择器中并正常常驻运行。
- 验收标准：真机设为壁纸后，桌面持续循环播放；灭屏/锁屏/打开其他应用全屏均正确暂停续播；重启手机后壁纸自动恢复。

### 阶段四：管理应用与体验完善
- 目标：MAUI 管理界面（选择视频、预览、设为壁纸、基础设置：静音/亮度/填充模式）、导入流程、错误处理、功耗打磨。
- 验收标准：完整用户流程走通（选视频→预览→设壁纸），连续多天日常使用无异常耗电崩溃。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Media3 ExoPlayer 的 C# NuGet 绑定包与当前 .NET Android 版本兼容性问题 | 阶段二可能受阻 | 备选方案 A：降级绑定包版本；备选方案 B：V1 退回系统 MediaPlayer（牺牲部分无缝度与格式兼容） |
| MAUI 工程中 WallpaperService 组合的资料少、踩坑多 | 阶段三周期拉长 | 服务层代码不依赖 MAUI（纯 .NET for Android 写法），把 MAUI 的影响面限制在管理 UI |
| OriginOS / ColorOS（iQOO / OPPO）对后台进程、壁纸常驻的激进省电策略 | 壁纸被杀、暂停策略行为异常 | 双真机（Neo 9 + Reno6 Pro）实测对照；引导用户加白名单；阶段三专列"国产 ROM 行为记录"小节 |
| 个别视频编码在原生循环下接缝明显 | 体验打折 | 风险预案：交叉淡化预处理提前到 V1 收尾（见 4.2） |
